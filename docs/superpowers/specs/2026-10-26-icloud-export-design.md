# icloud-export — дизайн

Дата: 2026-10-26

## Цель

Локальная утилита для macOS: выгрузить из iCloud Photos файлы выбранных альбомов
(включая «Скрытые» и «Недавно удалённые») в максимальном качестве, с корректными
метаданными внутри файлов и датами создания/изменения файлов, равными дате съёмки.
Повторный запуск в ту же папку докачивает только новое.

## Решения (согласовано)

| Вопрос | Решение |
|---|---|
| Платформа | Только macOS (нужен birthtime через `setattrlist`, Homebrew) |
| Поставка | `icloud-export.app` с одним бинарником Go внутри; фронтенд (Svelte + Bootstrap) встроен через `embed` |
| Окно | Собственное нативное окно на системном WKWebView (без браузера); флаг `--browser` — открыть UI в браузере (отладка) |
| Сборка | Только в Docker-контейнере, кросс-компиляция под `darwin/arm64` без cgo |
| Авторизация | Пароль Apple ID + 2FA (SRP через idmsa.apple.com). Пароли приложений iCloud Photos не принимает — в UI это объясняется |
| Альбомы | Пользовательские, смарт-альбомы, «Скрытые» (обязательно), «Недавно удалённые» |
| Режим | Докачка: повторный запуск качает только новое/изменённое, ничего не удаляет |
| Версия файла | Есть правки → отредактированная версия **вместо** оригинала; нет правок → оригинал |
| Live Photo | Фото + видео (`IMG_1234.HEIC` + `IMG_1234.MOV`) |
| Метаданные | Пишутся внутрь файла через `exiftool`. XMP-сайдкар — только для того, что в файл не ушло (нет exiftool / формат не принял поле) |
| exiftool | Опционален. Нет в системе → UI предлагает «Установить через Homebrew» (`brew install exiftool`), нет brew → инструкция |
| Даты файлов | birthtime и mtime = дата съёмки из iCloud (с учётом исправлений в «Фото») |
| Раскладка | Опция: **в одну папку** или **по датам `ГГГГ/ММ/`**. Альбомы → ключевые слова в метаданных. Hardlink'и не делаем |

Вне рамок: Windows/Linux, синхронизация с удалением, общая медиатека
(iCloud Shared Photo Library, зона `SharedSync`), iCloud Китая, загрузка в iCloud.

## Архитектура

Бинарник `icloud-export` при запуске поднимает HTTP-сервер на `127.0.0.1:<случайный порт>`
и открывает собственное окно (WKWebView) на `http://127.0.0.1:<port>/?t=<токен>`.
Все API-запросы требуют этот токен (заголовок) — защита от обращений других сайтов
к localhost (актуально в режиме `--browser`). Закрытие окна, Cmd+Q или Ctrl+C — завершение.

### Нативное окно без cgo

Сборка идёт в Linux-контейнере, поэтому cgo (и `webview/webview_go`, которому нужен
macOS SDK) недоступен. Окно делается через `github.com/ebitengine/purego/objc` —
вызовы Objective-C runtime без cgo, бинарник кросс-компилируется с `CGO_ENABLED=0`:

- `NSApplication` + главное меню (О программе, Скрыть, Выйти, Правка — для Cmd+C/V/A в полях ввода);
- `NSWindow` (~1100×750, запоминание размера не делаем) с `WKWebView`, грузящим локальный URL;
- делегат окна/приложения (зарегистрированный через `objc.RegisterClass`) — завершение при закрытии окна;
- `NSOpenPanel` для выбора папки назначения (вызывается из Go по запросу UI, на главном потоке).

Весь UI-код Cocoa — в пакете `internal/ui/macwindow` (`//go:build darwin`), главный поток
закреплён `runtime.LockOSThread` в `init`. **Риск:** если purego-путь упрётся в ограничение,
запасной вариант — режим `--browser` по умолчанию; решение принимается на шаге проверки окна.

### Пакеты Go

| Пакет | Ответственность |
|---|---|
| `internal/icloud/auth` | SRP-6a вход (`signin/init` → `signin/complete`, протоколы `s2k`/`s2k_fo`, PBKDF2-SHA256), 2FA (код с доверенного устройства, SMS как запасной путь), `2sv/trust`, `setup.icloud.com/.../accountLogin`. Восстановление сессии из сохранённых cookies + trust-token |
| `internal/icloud/photos` | Клиент CloudKit (`com.apple.photos.cloud`, зона `PrimarySync`): проверка индексации, список альбомов, постраничная выборка ассетов альбома, разбор записей `CPLAsset`/`CPLMaster` в доменную модель `Asset` |
| `internal/export` | Движок: план выгрузки, пул загрузчиков, докачка, переименование при коллизиях, прогресс-события |
| `internal/meta` | Обёртка над `exiftool -stay_open`, генерация XMP-сайдкара, установка birthtime/mtime |
| `internal/state` | Индекс выгрузки в корне папки назначения |
| `internal/web` | REST + SSE, раздача встроенной статики |
| `internal/ui/macwindow` | Нативное окно, меню, `NSOpenPanel` (purego/objc) |
| `web/` | Svelte-приложение (Vite), собирается в `web/dist`, встраивается |

### Хранение сессии

`~/Library/Application Support/icloud-export/session.json` (права 0600): cookies,
trust-token, `dsid`. Пароль на диск не пишется и в памяти не хранится после входа.
Сессия живёт ~2 месяца; по истечении — снова логин + 2FA.

## iCloud Photos API

Смарт-альбомы — запросы `records/query` с типами:

| Альбом | recordType |
|---|---|
| Все фото | `CPLAssetAndMasterByAssetDateWithoutHiddenOrDeleted` |
| Скрытые | `CPLAssetAndMasterHiddenByAssetDate` |
| Недавно удалённые | `CPLAssetAndMasterDeletedByExpungedDate` |
| Избранное, Видео, Селфи, Панорамы и т.д. | `CPLAssetAndMasterInSmartAlbumByAssetDate` + фильтр `smartAlbum` |
| Пользовательские альбомы | список `CPLAlbumByPositionLive`, содержимое — `CPLContainerRelationLiveByAssetDate` с `parentId` |

Папки альбомов показываются деревом, папка как таковая не выбирается — только альбомы.

Из записи берём:
- `CPLMaster`: `filenameEnc`, `resOriginalRes` (+ `resOriginalFileType`), `resOriginalVidComplRes` (видео Live Photo).
- `CPLAsset`: `assetDate`, `timeZoneOffset`, `addedDate`, `adjustmentType`, `resJPEGFullRes` / `resVidFullRes` (рендер правок, если есть), `isFavorite`, `captionEnc`, `locationEnc`/`locationV2Enc`, `isHidden`, `isDeleted`, `recordChangeTag`.

**Риск:** доступ к «Скрытым» через веб-API не документирован. Первый шаг реализации —
проверка на реальном аккаунте, что альбом отдаёт ассеты и ссылки на загрузку.

**Advanced Data Protection:** если включена, требуется «Доступ к данным iCloud
через веб» на устройстве; UI распознаёт ошибку доступа и показывает инструкцию.

## Выгрузка

### Выбор версии

- Если `adjustmentType` задан и есть `resJPEGFullRes`/`resVidFullRes` — качаем рендер правок.
- Иначе — `resOriginalRes`.
- Live Photo: фото по правилу выше + видео (отредактированное, если есть, иначе `resOriginalVidComplRes`).

### Имена и раскладка

- Базовое имя — из `filenameEnc` (`IMG_1234`), расширение — по фактическому типу скачиваемого ресурса.
- Видео Live Photo — то же базовое имя, `.MOV`.
- Раскладка «по датам»: `ГГГГ/ММ/` по дате съёмки в часовом поясе снимка (`timeZoneOffset`); без даты → `unknown/`.
- Коллизия имён в одной папке (разные ассеты с одинаковым `IMG_1234`) → `IMG_1234_<6 символов id>.HEIC`. Имя фиксируется в индексе, поэтому стабильно между запусками.
- Ассет из нескольких выбранных альбомов скачивается один раз.

### Докачка и индекс

Файл `.icloud-export.json` в корне папки назначения:
`assetId → {path, livePath, changeTag, size, layout}`.

- Ассет есть в индексе, файл на месте, размер совпадает, `changeTag` не изменился → пропуск.
- `changeTag` изменился (например, фото отредактировали) → перекачка с перезаписью того же пути.
- Файл пропал локально → перекачка.
- Индекс пишется атомарно (tmp + rename) каждые N файлов и при завершении.
- Загрузка идёт в `*.part`, после успеха — rename. Незавершённые `*.part` при старте удаляются (это наши временные файлы).
- Смена раскладки при существующем индексе — предупреждение в UI; старые файлы не трогаем, новые пути пишутся заново.

### Параллельность и ошибки

- Пул загрузчиков, по умолчанию 4 (настраивается 1–16).
- Ретраи с экспоненциальной задержкой на сетевые ошибки, 5xx и 429 (до 5 попыток).
- Ссылки на загрузку временные: при 403/410 перезапрашиваем запись ассета и берём свежую ссылку.
- 401/истёкшая сессия → пауза выгрузки и запрос повторного входа в UI, затем продолжение.
- Ошибка по одному ассету не останавливает выгрузку; список ошибок — в UI и в `.icloud-export-errors.log`.
- Пауза/отмена: текущие загрузки дорабатывают или прерываются, индекс сохраняется.

## Метаданные

Источник — данные iCloud (они учитывают правки, сделанные в «Фото»).

| Поле | Фото (JPEG/HEIC/PNG) | Видео (MOV/MP4) |
|---|---|---|
| Дата съёмки + пояс | `EXIF:DateTimeOriginal`, `CreateDate`, `OffsetTimeOriginal`, `XMP:DateCreated` | `QuickTime:CreateDate`, `Keys:CreationDate` |
| GPS | `GPSLatitude/Longitude/Altitude` (+ Ref) | `Keys:GPSCoordinates` |
| Подпись | `XMP-dc:Description`, `EXIF:ImageDescription`, `IPTC:Caption-Abstract` | `Keys:Description` |
| Избранное | `XMP:Rating=5` | `XMP:Rating=5` |
| Альбомы, Скрыто, Удалено | `XMP-dc:Subject`, `IPTC:Keywords` (напр. «Отпуск 2024», «Hidden», «Recently Deleted») | `XMP-dc:Subject` |

- С `exiftool`: один процесс `-stay_open True`, запись с `-overwrite_original`. Если exiftool вернул ошибку/предупреждение для поля — это поле уходит в сайдкар.
- Без `exiftool`: всё уходит в `IMG_1234.HEIC.xmp`.
- После записи метаданных: birthtime и mtime файла (и сайдкара, и видео Live Photo) = дата съёмки, через `setattrlist` (`ATTR_CMN_CRTIME`) и `os.Chtimes`.

## UI

1. **Вход.** Apple ID, пароль, пояснение: «нужен основной пароль Apple ID; пароли приложений
   (account.apple.com) iCloud Photos не поддерживает» + ссылка на support.apple.com/102654.
   Затем поле кода 2FA (+ «Отправить SMS»).
2. **Альбомы.** Дерево альбомов с чекбоксами и количеством; «Скрытые» и «Недавно удалённые»
   отдельной группой. Папка назначения (путь вводом + кнопка «Выбрать…» → `NSOpenPanel`).
   Раскладка: «В одну папку» / «По датам ГГГГ/ММ». Параллельность.
   Статус exiftool: найден (версия) / не найден → кнопка «Установить через Homebrew» или инструкция.
3. **Выгрузка.** Общий прогресс (файлы и байты), скорость, текущие файлы, счётчики
   «скачано / пропущено / ошибки», список ошибок, «Пауза», «Отмена».

Прогресс приходит по SSE (`/api/events`).

## Тестирование

- Unit: SRP по тестовым векторам, разбор записей CloudKit по сохранённым фикстурам
  (обезличенным), выбор версии и имени, коллизии, раскладка, индекс/докачка,
  генерация XMP, построение аргументов exiftool, установка birthtime (на временном файле).
- Тесты гоняются в контейнере (linux), кроме darwin-специфичных (birthtime, окно):
  для них `go test -c` с `GOOS=darwin` в контейнере, готовый тестовый бинарник запускается на хосте.
- Интеграционный: фейковый CloudKit-сервер (`httptest`) + полный прогон выгрузки в tmp-папку,
  повторный прогон — 0 загрузок.
- Ручная проверка на реальном аккаунте: вход + 2FA, «Скрытые», «Недавно удалённые»,
  отредактированное фото, Live Photo, видео; проверка метаданных `exiftool -a -G1` и
  дат через `stat -f '%SB %Sm'`.

## Сборка

Всё в Docker, на хосте ничего кроме Docker не нужно (Go/Node не ставятся):

- `Dockerfile.build` (multi-stage): `node` — `npm ci && npm run build` в `web/`;
  `golang` — `CGO_ENABLED=0 GOOS=darwin GOARCH=arm64 go build` (Go-линкер сам делает ad-hoc подпись,
  обязательную на Apple Silicon); сборка `.app`: `Info.plist`, бинарник, `icon.icns` (генерируется
  из PNG Go-скриптом).
- `make app` → `docker build` с выводом артефакта в `dist/icloud-export.app`.
- `make test` → тесты в контейнере; `make test-darwin` → сборка darwin-тестов в контейнере и запуск на хосте.
- В рантайме зависимостей нет, кроме опционального exiftool.
